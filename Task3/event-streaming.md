### 1. Топики

| Топик                        | Производитель | Потребители (группы)                                        | Ключ партиции | Партиций | Хранение                                  | Формат    |
| ---------------------------- | ------------- | ----------------------------------------------------------- | ------------- | -------- | ----------------------------------------- | --------- |
| `campaign.changes.v1`        | Campaign      | `bidding-snapshot`, `delivery-snapshot`, `analytics-loader` | `campaign_id` | 6        | уплотнение (последнее состояние по ключу) | JSON      |
| `ad.auction-won.v1`          | Bidding       | `events-matcher`                                            | `campaign_id` | 24       | 7 суток                                   | Avro      |
| `ad.impressions.v1`          | Delivery      | `events-matcher`                                            | `campaign_id` | 48       | 7 суток                                   | Avro      |
| `ad.clicks.v1`               | Delivery      | `events-matcher`                                            | `campaign_id` | 24       | 7 суток                                   | Avro      |
| `billing.billable-events.v1` | Events        | `billing-charger`, `analytics-loader`, `frequency-counter`  | `campaign_id` | 24       | 30 суток                                  | Avro      |
| `*.retry`                    | потребители   | те же группы                                                | наследует     | 6        | 3 суток                                   | наследует |
| `*.dlq`                      | потребители   | ручной разбор                                               | наследует     | 3        | 30 суток                                  | наследует |
|                              |               |                                                             |               |          |                                           |           |

**Почему ключ `campaign_id`:** порядок гарантируется только внутри партиции. События одной кампании должны обрабатываться последовательно (иначе «кампания остановлена» может примениться раньше «бюджет пополнен») и одним потребителем (иначе конкуренция за одну строку баланса).

**Почему уплотнение для `campaign.changes`:** брокер хранит по каждому ключу последнее событие. Новый экземпляр Bidding, прочитав топик с начала, получает актуальное состояние всех кампаний — один механизм закрывает и прогрев, и последующие обновления, отдельный эндпоинт снапшота не нужен.

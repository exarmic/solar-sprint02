### Место в архитектуре и функции

Единая точка входа для машинного трафика DSP-партнёров. Разделение ответственности: шлюз занимается транспортом, аутентификация, фильтрация с лимитами, преобразование форматов; вся предметная логика — в Bidding Service. Агрегация данных для интерфейсов к шлюзу не относится (это Dashboard BFF).

| Функция                 | Реализация                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------- |
| Завершение TLS          | сертификаты на шлюзе, к сервисам — внутреннее шифрование                                          |
| Аутентификация партнёра | взаимный TLS (основной способ) либо ключ в заголовке; идентификатор партнёра прокидывается дальше |
| Ограничение частоты     | лимит на партнёра и общий защитный лимит                                                          |
| Маршрутизация           | по типу запроса и по весам между старым и новым путём (в переходный период)                       |
| Circuit Breaker         | выявление сбойных экземпляров и их временное исключение                                           |
| Таймауты и дедлайны     | верхняя граница обработки из `tmax`, передача дедлайна дальше                                     |
| Замер SLA               | распределение времени отклика по партнёрам, доля ответов вне 80 ms                                |

### 2. Маршрутизация и постепенный перевод

| Входящий путь             | Целевой сервис     | Протокол | Таймаут | Повторы                                                     | Распределение трафика  |
| ------------------------- | ------------------ | -------- | ------- | ----------------------------------------------------------- | ---------------------- |
| `POST /openrtb/2.6/bid`   | Bidding Service    | gRPC     | 75 ms   | запрещены - увеличивает таймаут. <br>только circuit breaker | 10% (растёт по этапам) |
| `POST /openrtb/2.6/bid`   | Монолит, Ad Server | HTTP     | 75 ms   | запрещены                                                   | 90% (убывает)          |

| `GET /openrtb/2.6/win/v1` | Монолит, Ad Server | HTTP     | 500 ms  | 2, с нарастающей задержкой                                  | 100%                   |

### 3. Ограничение частоты

Двухуровневое:
**по партнёру** — согласованный контрактом предел (превышение → `429` с указанием времени повтора), 
**общий** — защита от исчерпания ёмкости (превышение → `204`, а не `429`: для аукциона отказ от участия корректнее ошибки).

Добавляем алгоритм  «текущее ведро» с пополнением (token bucket), который допускает короткие всплески в пределах ёмкости ведра, ограничивая среднюю интенсивность. 
Счётчики общие для всех экземпляров шлюза в Redis, атомарно; при его недоступности шлюз переходит на локальные лимиты с уменьшенным порогом (сознательная деградация в сторону безопасности).

### 4. Размыкатель на шлюзе

Экземпляр сервиса ставок временно исключается из балансировки при превышении доли ошибок или доли ответов, вышедших за таймаут, в период окна наблюдения. Возврат — через нарастающую паузу и пробный трафик. Одновременно исключается не более заданной доли экземпляров — иначе при массовой деградации шлюз отключит всех и превратит частичный отказ в полный.

Когда в балансировке не остаётся пригодных экземпляров нового пути, трафик уходит на старый (монолит) — это работает, пока Strangler Fig не завершён, и является дополнительным аргументом не спешить с выключением старого пути.

### 5. Мониторинг времени отклика и доказательство SLA

**Точка замера — шлюз.** Это граница нашей ответственности: она включает обработку и внутреннюю сеть, но не публичную сеть до партнёра. Измерение партнёра всегда будет выше на сетевую задержку — именно поэтому внутренний бюджет 60 ms жёстче контрактных 80 ms.

Метрики: распределение времени отклика (P50/P95/P99) по партнёрам и по маршрутам; доля ответов вне 80 ms; доля отказов от участия с причинами (дедлайн, нет кандидатов, квота исчерпана); доля ошибок; состояние размыкателя.

Пороги оповещения: доля ответов вне 80 ms выше целевой на скользящем окне; P99 выше внутреннего бюджета; размыкатель сработал; расхождение метрик шлюза и сервиса (признак проблем в сети или в самом шлюзе).

Для разбора претензий — почасовые выгрузки по партнёру, хранение не менее срока предъявления претензий по контракту.
